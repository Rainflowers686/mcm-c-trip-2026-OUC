## 二、使用环节说明

### 2.1 模型口径讨论与审查

AI 工具用于辅助讨论问题一、问题二、问题三的建模边界，包括 Day1 / Day5 时间边界、早到等待、可靠度定义、失败事件定义、target90 方案定位等。AI 工具也用于检查论文是否存在旧口径残留，例如误把 `p_peak=0.6`、`p_off=0.3` 写成题目给定参数，或误把 target90 写成问题二主方案。

### 2.2 代码草案与工程实现辅助

Codex / 编程辅助工具用于辅助修改 Python 工程，包括问题一评分输出、问题二枚举求解、问题三蒙特卡洛模拟、诊断实验、target90 可靠性优先实验及合法性审计脚本。代码由参赛队在本地运行，报错处理、结果核验和是否采纳均由参赛队人工确认。

### 2.3 结果整理与表格生成

AI 工具用于将 `baseline_plan.json`、`reliability_report.json`、`diagnostic_report.json`、`target90_report.json`、`target90_audit.json` 等程序输出整理为论文可用表格、图表清单和结果摘要。论文中的关键数字以本地程序输出文件为准，不采用 AI 凭空生成的数值。

### 2.4 论文文本辅助

AI 工具用于辅助生成论文初稿、检查硬伤、压缩摘要、统一表述口径、整理图表插入位置、生成队内交接说明和支撑材料说明。论文中的核心模型、核心结论和最终表述由参赛队人工审核后采纳。

## 四、人工审核与修改说明

AI 输出未被直接无条件采纳。参赛队进行了以下人工审核：

1. **题意与约束确认**  
   参赛队根据赛题原文确认景点数量、每日景点数、最小游览时长、酒店入住退房、Day1 / Day5 边界和五日联合可靠度定义。

2. **程序运行与结果核验**  
   所有 Python 脚本均由参赛队在本地环境运行。关键结果包括可行解数量、recommend 行程、三方案可靠度、诊断实验、敏感性扫描、target90 结果与审计结论，均经过人工查看和交叉核对。

3. **数学公式与数值一致性检查**  
   参赛队复核了综合得分公式、benefit-normalized 归一化、蒙特卡洛可靠度定义、Shapley 分解、Day1 / Day5 时间边界等关键部分。对于 AI 审稿指出的问题，参赛队按最终口径做了局部修补。

4. **论文表述风险控制**  
   对于 target90 方案，参赛队确认其定位为“问题三可靠性优先备用方案”，不替代问题二 recommend 主方案；同时确认其没有修改堵车概率、排队分布、失败标准和五天联合可靠度定义。

5. **最终采纳决策**  
   是否保留某一模型设定、某一实验结果或某一论文表述，均由参赛队成员讨论后决定，AI 工具只提供辅助建议。

## 五、未使用 AI 独立完成的部分

以下部分未由 AI 独立完成，而是由参赛队人工提供、运行、确认或最终决定：

1. 赛题原文阅读、约束理解与最终采纳；
2. 原始数据文件的准备与核对；
3. 本地代码运行、输出文件生成与结果确认；
4. 是否采用 v1.1.1 时间边界、五套偏好方案和 target90 第六方案的最终决策；
5. 所有论文关键结论的最终确认；
6. 论文终稿排版、图表插入、参考文献补充和最终提交。

## 六、风险控制说明

1. **结果数值只来自程序输出文件**  
   论文关键数值以 `baseline_plan.json`、`reliability_report.json`、`diagnostic_report.json`、`target90_best_plan.json`、`target90_report.json`、`target90_audit.json` 和 CSV / PNG 输出为准。

2. **保留完整支撑材料**  
   程序源代码、输入数据、JSON 输出、CSV 表格、PNG 图件和 log 文件整理进支撑材料压缩包 `mcm_c_trip_project_v111.zip`。

3. **设置高风险表述禁用清单**  
   终稿前避免以下错误表述：
   - “target90 是问题二最终最优方案”；
   - “通过调参达到 90%”；
   - “前五套方案失败所以模型错误”；
   - “p_peak / p_off 是题目给定参数”；
   - “整体可靠度改成日均可靠度”。

4. **人工保留最终解释权**  
   AI 工具不参与最终评分、排名、提交决策。所有模型设定、结果解释和论文表述均由参赛队最终确认。
