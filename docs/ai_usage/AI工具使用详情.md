## 二、使用环节说明

AI 工具主要用于以下辅助环节：

1. **模型口径讨论与审查**  
   辅助梳理问题一、问题二、问题三的建模边界，讨论 Day1 / Day5 时间边界、早到等待、可靠度定义、失败事件定义等口径；同时对可能存在的旧口径、错误公式和不严谨表述进行审查。

2. **代码草案与工程实现辅助**  
   辅助生成和修改 Python 求解脚本，包括问题一评分输出、问题二枚举求解、问题三蒙特卡洛模拟、诊断实验、target90 可靠性优先实验及审计脚本。代码运行、报错处理、输出校验和结果是否采纳均由参赛队人工确认。

3. **结果整理与表格生成**  
   辅助将 `baseline_plan.json`、`reliability_report.json`、`diagnostic_report.json`、`target90_report.json`、`target90_audit.json` 等结果文件整理成论文可用表格和说明材料。

4. **论文文本辅助**  
   辅助生成论文初稿、修补硬伤、压缩重复表述、降低模板化表达，并整理图表插入位置、参考文献占位和论文手待办清单。

5. **风险提示与最终审查**  
   辅助检查以下风险点：是否误把 `p_peak=0.6`、`p_off=0.3` 写成题目给定；是否把 target90 写成问题二主方案；是否把低可靠度解释为模型失败；是否存在旧口径残留；图表编号和结果数值是否一致。

## 三、人工审核与修改说明

AI 输出未被直接无条件采纳。参赛队对所有关键内容进行了人工审核，主要包括：

1. **题意与建模口径人工确认**  
   参赛队成员根据赛题原文确认了景点数量、每日景点数、每日活动窗口、最小游览时长、酒店入住退房、Day1 / Day5 边界等约束。

2. **程序运行与结果核验**  
   所有 Python 脚本均由参赛队在本地环境运行。关键结果包括可行解数量、recommend 行程、可靠度结果、诊断实验结果、target90 结果与审计结论，均经过人工查看和交叉核对后才写入论文。

3. **数学公式和数值一致性检查**  
   参赛队对综合得分公式、benefit-normalized 归一化、蒙特卡洛可靠度定义、Shapley 分解、Day1 / Day5 时间边界等关键部分进行了复核。对于 AI 审稿指出的问题，参赛队按最终口径做了局部修补。

4. **论文表述风险控制**  
   对于 target90 方案，参赛队人工确认其定位为“问题三可靠性优先备用方案”，不替代问题二 recommend 主方案；同时确认其没有修改堵车概率、排队分布、失败标准和五天联合可靠度定义。

5. **最终采纳决策**  
   是否保留某一模型设定、某一实验结果或某一论文表述，均由参赛队成员讨论后决定，AI 工具只提供辅助建议。

## 四、未使用 AI 独立完成的部分

以下部分未由 AI 独立完成，而是由参赛队人工提供、运行、确认或最终决定：

1. 赛题原文阅读、约束理解与最终采纳；
2. 原始数据文件的准备与核对；
3. 本地代码运行、输出文件生成与结果确认；
4. 是否采用 v1.1.1 时间边界、五套偏好方案和 target90 第六方案的最终决策；
5. 所有论文关键结论的最终确认；
6. 论文终稿排版、图表插入、参考文献补充和最终提交。

## 五、风险控制说明

为降低 AI 辅助带来的不确定性，本队采取了以下控制措施：

1. **结果数值只来自程序输出文件**  
   论文中的关键数值以 `baseline_plan.json`、`reliability_report.json`、`diagnostic_report.json`、`target90_best_plan.json`、`target90_audit.json` 和 CSV/PNG 输出为准，不采用 AI 凭空生成的数值。

2. **保留完整支撑材料**  
   程序源代码、输入数据、JSON 输出、CSV 表格、PNG 图件和 log 文件已整理进支撑材料压缩包 `mcm_c_trip_project_v111.zip`。

3. **对高风险表述设置禁用清单**  
   终稿前需全文搜索并避免以下错误表述：
   - “target90 是问题二最终最优方案”；
   - “通过调参达到 90%”；
   - “前五套方案失败所以模型错误”；
   - “p_peak / p_off 是题目给定参数”；
   - “整体可靠度改成日均可靠度”。

4. **人工保留最终解释权**  
   AI 工具不参与最终评分、排名、提交决策。所有模型设定、结果解释和论文表述均由参赛队最终确认。
